# D-170 — The project graph inspector shows the analysis it already holds, and page previews become schematic
**Status:** accepted (2026-11-12); the labelled preview surface is superseded by D-176 (the cards now carry a label-free mini-page and the inspector no longer draws the node tree)

**Context.** Owner request (2026-11-12): the backend already gives enough information but the graph frontend was too thin, and the frontend half — pages and frontend code — was barely visible; "no alternative views", add the missing information inside the existing panel, with page previews. The graph already drew page/route/table/view/workflow cards with fullscreen, filters and a committed layout (D-092/D-126/D-134/D-160/D-161), but the inspector only expanded pages (a capped name tree), views and workflows; route and table nodes ended in a two-line stub, and no surface ever showed project source. Yet the panel already holds the whole `Analysis` object (`fileFacts`, `routes`, `tables`, `relations`, `pages`, `workflowTables`) and `loadProjectAnalysis` has already read every project source (`loadProjectSources`, cached per snapshot); each fact carries a `SourceRef {file, line}`.

**Decision.** Keep one graph and one view mode. Enrich the inspector and the analyzer additively:
- **Analyzer.** `PagePreviewNode` gains optional `text` (a direct literal/template child, or a control's `placeholder`/`aria-label`/`value`/`alt` attribute) and `tKey` (a direct `t("key")` child, D-043), read only from elements that produce a node. Intrinsics producing a node now include the **content intrinsics**: copy-bearing text elements (`p`/`span`/`strong`/`em`/`small`/`b`/`i`/`code`/`pre`/`blockquote`/`h4`–`h6`), emitted only when they carry readable copy; controls (`button`/`a`/`input`/`select`/`textarea`/`label`) and media (`img`/`video`/`audio`), emitted even without copy because they are visible blocks. Layout-only wrappers (`div`) stay flattened, and the content nodes have their own budget (30 per page) so they cannot starve the structural budget (60, unchanged). Node order, the depth budget, cycle cuts and the `dynamic` flag do not change. The graph id helpers (`pageId`/`routeId`/`tableId`/`viewId`/`workflowId`) are exported so the IDE joins by id instead of re-deriving the spelling.
- **IDE model.** `graph-details.ts` joins the `Analysis` facts to node ids: route db columns, `crossSite`/`rawSql`/handler reads, static db usage (`relations`), elevations with operation/tables/source line; table column defaults, policies and foreign keys; page static calls; workflow derived table surface. `graph-source-snippet.ts` extracts a line-anchored snippet from the cached sources.
- **Preview surfaces.** The inspector becomes a router over per-kind sections (route/table/page/view/workflow) with `ProjectGraphSourcePreview` and an "open in preview" action for a page. `ProjectGraphPreview` becomes a schematic React semi-render of the page: adapter blocks for the section and content intrinsics the preview produces (headings and paragraphs with their copy, action/field/media blocks carrying button copy, input placeholders and image alt text), component cards with resolved file/line, placeholder rows for `ul` (its `li` children are flattened), labels resolved through `Analysis.locales`/`defaultLocale` (`tKey` first, `text` fallback). It is explicitly a structure with placeholder data, never CSS or a mounted React tree.
- **Open in preview** reuses the existing PreviewPanel: navigate the bound preview tab, else add one that already carries the page path; `preview-session.ts` gains only `addPreviewTab(url, path)` returning the id and `setPreviewPath`.
- **Deferred by this decision:** AI tools to highlight paths (`graph_highlight`/`graph_paths`) and to screenshot the graph; a mocked-data live preview (Service-Worker fetch interception); component/lib graph nodes (D-134 stays); richer preview facts (component props, nested `li` items, deeper budgets).

**Consequences.** No contract removed and no layout/persistence change: old `.facilis/graph` files stay valid, and the AI `graph_state`/`graph_arrange` surface is untouched. The preview node fields are additive and optional, so an older analyzer worker still renders (field absence means "unknown label", not empty). A page preview can now hold up to 90 nodes (60 structural + 30 content), still bounded and only in memory. The page model still keeps only `src/pages/**` nodes; the frontend code becomes visible through the inspector's composition tree, source snippets and component cards, not through new node kinds. Deploy/origin behavior is unchanged: the preview is the existing panel, reachable only when the project runs.

**Verification.** `pnpm --filter @facilis.dev/analyze test` (26 files / 172 tests; the text tests cover literal text, `t()`/`i18n.t()` keys, templates, whitespace collapse and nested isolation; the content tests cover paragraphs/headings/inline copy, button/input/img copy, attribute fallbacks, dynamic-only copy and the separate content/structural budgets) and `pnpm --filter @facilis.dev/ide test` (145 files / 1201 tests; new `graph-details.test.ts` 7, `graph-source-snippet.test.ts` 14, `graph-wireframe.test.ts` 58, `graph-open-preview.test.ts` 4, `preview-session.test.ts` 2 and the tab-binding cases in `preview-tabs.test.ts`; i18n placeholders parity). Root `pnpm lint`, `pnpm typecheck` and `pnpm build` pass; `node scripts/check-file-length.mjs` and `check-ide-theme.mjs` are green. The visual layer has no browser test in this slice (the repo has no component-test harness): the schematic preview is covered by its pure model, and the browser pass belongs to the next `pnpm ide:smoke:panels` run.
