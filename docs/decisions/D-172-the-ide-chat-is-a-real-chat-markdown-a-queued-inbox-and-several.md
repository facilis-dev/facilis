# D-172 — The IDE chat is a real chat: Markdown, a queued inbox and several conversations
**Status:** accepted (2026-11-12)

**Context.** Owner review of the chat (2026-11-12): "La chat non renderizza Markdown"; "Messaggi in chat durante il thinking … mi aspetto che il messaggio venga messo in coda e inviato nel primo momento utile. Ci deve essere mostrata la coda dei messaggi appena sopra"; "non si riescono a creare 2 o più chat". Three gaps behind them: the assistant's prose was rendered as plain text with only ``` fences styled (D-114 chose the plain block for density, but it also flattened real Markdown); `ChatComposer.submit()` returned silently while `ChatState.phase !== "idle"`, so a message typed during a turn was lost; `chat-host.ts` kept exactly one `ChatSession` per controller, so the header "+" (newChat) wiped the conversation it should have preserved.

**Decision.** Three additive changes on the existing chat session, no protocol or model-prompt change:
- **Markdown.** `ChatMarkdown.tsx` wraps `react-markdown` with `remark-gfm` (new IDE runtime dependencies) and only overrides styling with the existing role tokens: headings, lists, blockquote, inline code, the `bg-editor` fenced-code panel, GFM tables/strikethrough, links `target="_blank" rel="noreferrer"`. No `rehype-raw`: the compiler emits React elements, so model output can never inject markup. Assistant prose is Markdown; user bubbles stay literal text.
- **Queued inbox.** `ChatState.queued` is a per-conversation FIFO; `send()` enqueues while a turn is running instead of dropping the message, and the session drains it as soon as it settles back to idle (also after an abort, an error, Apply/Undo or a compaction; `newChat()` clears it). `removeQueued(id)` drops one row. `ChatQueueView` renders the pending rows just above the composer with a remove button; the composer keeps the textarea and Send enabled while busy, with Stop beside Send. `ChatQueue` and the `apply`/`undo` move (`chat-apply.ts`, mechanical) keep `chat-session.ts` at the 300-line limit.
- **Several conversations.** `ChatStore` (one per controller) holds a map of `ChatSession`s with an active id; `ChatPanel` subscribes through `useSyncExternalStore`, `ChatConversationsMenu` lists every conversation by a title derived from its first user message, "+" creates a new one and keeps the previous, deleting the active one selects the next (or a fresh chat) after aborting its turn and dropping its queue. The composer is keyed by the active id so drafts never leak across chats. In-memory only, exactly as before: reloading starts clean. One `McpSession` is shared by every conversation, and `chatFor()` stays as the active-session shim for view consumers (`ActivityBar` now follows the store too).

**Consequences.** The IDE takes on `react-markdown`/`remark-gfm` (React elements, no raw HTML path). Conversation history is still per page load; the settings (provider/model/key) remain global and are read when a session is constructed, so a provider change made in one conversation only reaches the others after a reload — the same staleness the single-session chat already had, now visible across chats. Markdown is rendered as GFM, so a model that answers in raw HTML shows the markup as text by design.

**Verification.** `pnpm --filter @facilis.dev/ide test` — 152 files / 1270 tests, including the new `chat-markdown` SSR tests (7), the queue cases in `chat-session.test.ts` (queue while sending, FIFO auto-send, removeQueued, newChat clears, failed turn keeps the queue) and `chat-store.test.ts` (8: create keeps the previous, select ignores unknown ids, per-conversation state survives switches, remove active/non-active/last, subscriptions). `typecheck`, `lint`, `node scripts/check-file-length.mjs` and the i18n parity test pass. The 2026-11-12 browser run (`pnpm ide:smoke`, dev mock provider) passed every chat check end to end: panel, mock provider, message typed and sent, streaming bubble, proposal, Apply, undo, project instructions; the run still exits non-zero on the data-explorer/query-console checks and the pre-existing `vite` reload console error, none of which touch this slice.
