# D-176 — The page card carries a label-free mini-page; the inspector drops the component tree
**Status:** accepted (2026-11-12; the miniature's layout follows the page kind in D-178)

**Context.** Owner review of D-170 the same day: "Recentemente abbiamo aggiunto una struttura più avanzata delle pagine, ma è abbastanza inutile … mi piacerebbe vedere una 'mini-paginetta' (tipo uno screenshot) all'interno del grafo … la struttura dei componenti è inutile e troppo dispersiva. Quindi: 1. deve stare nel grafo; 2. se non è un rendering fedele fatto bene, piuttosto struttura ma che non sia troppo dispersiva." D-170's semi-render was a labelled per-node structure: in the inspector column it read as the component hierarchy (AppLayout → ASIDE → LINK …), and it only existed in the sidebar, while the page card the owner looks at showed a bare "N sections" line.

**Decision.** Replace the labelled structure with one compact miniature, drawn on the page card and reused in the inspector:
- **Model.** `graph-page-sketch.ts` reads the same `PagePreview` facts and returns `{header, rail, blocks, truncated}`: the shell (a header intrinsic; an aside, or a nav outside the header) plus at most four coarse content regions — a form (fields and the actions that follow them merged), a list (`ul`/`ol`/`table`), media, copy (consecutive headings/paragraphs merged), one board per component whose children the analyzer did not expand, and one dashed branch for a run of conditional alternatives. A single conditional is noise and is skipped; overlay components (dialog/sheet/drawer/popover/tooltip/toast) are not part of a resting page and are skipped by name. Wrapper chains flatten with no box of their own, so an AppLayout → RequireAuth → Page chain never becomes hierarchy. No labels are drawn: at card size they would be unreadable and would rebuild the tree the owner rejected. `graph-wireframe.ts` and its labelled per-node renderer are deleted.
- **Surfaces.** `ProjectGraphPageSketch` draws a fixed 2:1 device frame — rail, optional top bar, weighted blocks with a slack spacer so a one-region page keeps a page-like proportion instead of one giant box — on the page card and, larger, in the inspector's "Static preview" section (with the existing note and the truncation hint). Page cards grow from 44 px to 157 px, the auto-layout page pitch from 88 px to 200 px, and the edge fallback plus the off-DOM screenshot scene use the measured 157 px. The inspector's "Components" chip list goes with the tree: it was the same inventory in another shape, and the source snippet, calls and links remain.
- **Facts.** No analyzer change: budgets, depth, node fields and `truncated` are untouched, so an older worker still renders.

**Consequences.** Saved `.facilis/graph` layouts keep their positions; page cards placed under the old 88 px pitch can overlap until the user drags or re-fits, because the miniature makes the card taller. The sketch stays explicitly schematic ("placeholder data — never a rendering") and has no component-test harness (D-171): the model is unit-tested, the React layer is covered by typecheck/lint, and the visual evidence is a throwaway browser render over the analyzer output of `examples/todo-app` (login/register/todos/not-found at card and inspector width).

**Verification.** `pnpm --filter @facilis.dev/ide test` — 157 files / 1281 tests (after rebasing onto main), including the new `graph-page-sketch.test.ts` (9: shell flattening, form merging, lone-conditional skip, overlay skip, header/nav disambiguation, copy merge, four-region cap, orphan promotion, truncation) and the updated `graph-scene.test.ts` page rect. `pnpm --filter @facilis.dev/ide typecheck`, `pnpm --filter @facilis.dev/ide lint` (0 errors) and `node scripts/check-file-length.mjs` pass; the i18n parity test covers the key removals and the reworded note. Visual check: the four template pages rendered from real analyzer facts at 224 px card width (157 px card, 104 px sketch) and at 320 px inspector width, plus the graph harness against a live WebContainer project.
