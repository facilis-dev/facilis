# IDE i18n + dark-mode checklist

D-043 makes both rules mandatory for anything this project adds or touches:

1. **No hardcoded user-facing strings.** Every string goes through `t()` from
   `ide/src/i18n` and lives in `ide/src/i18n/en.ts` (and, where translated,
   `ide/src/i18n/it.ts`). `pnpm --filter @facilis.dev/ide test` fails if a catalogue
   key is empty, unknown, or loses a `{placeholder}` in translation.
2. **No colour per component.** A theme is a complete block of `data-theme` role values
   in `index.css`; a component only names roles. The shadcn roles
   (`bg-background`, `bg-sidebar`, `bg-card`, `bg-accent`, `text-foreground`,
   `text-muted-foreground`, `border-border`, `ring-ring`, `bg-destructive`, …) are
   joined by the IDE chrome roles `chrome`, `editor`, `panel`, `overlay`, `brand`
   (+ `-foreground` each), `checker`, and the status roles `info`, `success`,
   `warning` (+ `-foreground`). Raw hex/palette colours survive only for scrims
   (`bg-black/10`), with a comment.

The theme is user-selectable from the command palette (Light / Dark / System); next-themes
writes `data-theme="facilis-light|facilis-dark"` on `<html>` (the pre-paint script applies it
before first paint), and `ui-themes.ts` maps a theme to its attribute and to the appearance
Monaco/xterm follow through `IdeController.applyUiTheme()`. xterm's base colours read
`--panel`/`--panel-foreground`, so the terminal follows a new theme as well. The locale is picked once at boot (`initI18n()`: the
saved choice, else the browser language, else English) and `document.documentElement.lang`
is kept in sync.

## Adding a theme

1. Add a complete `[data-theme="<name>"]` block to `ide/src/index.css` — every role the light
   block defines, and nothing else. Set `color-scheme` and the theme's `checker`.
2. Add an entry to `UI_THEMES` in `ide/src/ui-themes.ts`: attribute, appearance
   (`"light"`/`"dark"`, which Monaco/xterm follow) and a palette label key.
3. Add the label to `en.ts`/`it.ts` and a command-palette row (`setTheme("<name>")`).
4. No component changes: colors are roles. If a role is missing, add it to _every_ theme block
   rather than hardcoding a value in the component.

## Adding a string

1. Add the key to `ide/src/i18n/en.ts` (flat, namespace-first: `preview.newTab`).
2. Add the Italian translation to `ide/src/i18n/it.ts` (may be partial; falls back to English).
3. Use `t("preview.newTab")`; pass `{placeholders}` for dynamic values.
4. Run `pnpm --filter @facilis.dev/ide test` — the parity test checks both catalogues.
